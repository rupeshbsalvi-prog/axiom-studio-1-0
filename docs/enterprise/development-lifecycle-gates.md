# Development Lifecycle Gates

[Back to docs index](../README.md)

## Purpose

Define the lifecycle a feature or module must pass through before production readiness.

## Lifecycle

1. Idea.
2. Research.
3. Requirement gathering.
4. Business analysis.
5. User research.
6. Wireframe.
7. UX design.
8. UI design.
9. Prototype.
10. Architecture.
11. Database design.
12. API design.
13. Frontend development.
14. Backend development.
15. Integration.
16. Testing.
17. Performance testing.
18. Security testing.
19. User acceptance testing.
20. Release candidate.
21. Production deployment.
22. Monitoring.
23. Maintenance.
24. Version upgrade.

## Gate Rule

Not every feature needs a heavy process, but enterprise modules and Imagine X capabilities must explicitly pass lifecycle gates or document why a gate is not applicable.

## Required Evidence

- Requirement document or issue.
- Acceptance criteria.
- Design or UX note when user-facing.
- Architecture note or ADR when structural.
- Test evidence.
- Release note.
- Operational or monitoring note when production-impacting.

## Locked Baseline

Changes require an ADR.
