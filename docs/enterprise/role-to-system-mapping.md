# Role to System Mapping

[Back to docs index](../README.md)

## Purpose

Map enterprise software company roles into concrete Axiom systems.

## Mapping

| Role Family | Axiom System Expression |
|---|---|
| Product Management | roadmap, requirements, backlog, studio acceptance criteria |
| Architecture | contracts, package boundaries, runtime model, ADRs |
| Engineering | apps, packages, crates, services, integrations |
| UI / UX | app shell, studio ergonomics, design system, prototypes |
| Frontend | React surfaces, canvas interaction, client state |
| Backend | APIs, jobs, auth, provider connections |
| Database | persistence schemas, migrations, AXPKG metadata |
| AI | Axiom Imagine X, agents, memory, routing, evals |
| DevOps | CI/CD, environments, monitoring, release automation |
| Security | secrets, auth, RBAC, audit, compliance |
| QA | test plans, automation, E2E, performance, UAT |
| Documentation | docs, API references, release notes, knowledge base |
| Support | diagnostics, incident workflows, support dashboards |
| Deployment | build, packaging, deployment, production administration |
| Analytics | dashboards, product metrics, reporting |

## Imagine X Use

Imagine X can use these role mappings as internal specialist roles during planning. For example, a large feature request can be reviewed by product, design, architecture, frontend, backend, AI, QA, security, documentation, and release roles before it becomes an implementation plan.
