# Project Memory

[Back to docs index](../README.md)

## Product

Axiom Studio 1.0 is the clean build of an AI-native creative operating system.

## Core Memory

- The project begins with documentation only.
- The source projects remain untouched references.
- The first implementation target is a stable shell plus one vertical creative workflow.
- All studios must share canvas, project, auth, provider, brain, export, and replay systems.

## Best Ideas to Preserve

- From `Axiom-Studio-main`: deterministic semantic runtime, replay certification, governance, collaboration doctrine, plugin architecture.
- From `Axiom Studio`: Axiom Brain, FastAPI backend, generation jobs, provider connections, guardian/repair tests, desktop/Tauri patterns.
- From `axiom-studio-creative-suite`: polished shell, AXP/Prism visual language, 10 studios, universal canvas engine, AXPKG persistence.

## Non-Negotiables

- AI is not authoritative.
- GPU output is projection-only.
- User-approved semantic commands are the source of truth.
- Project persistence must be durable, recoverable, and portable.
