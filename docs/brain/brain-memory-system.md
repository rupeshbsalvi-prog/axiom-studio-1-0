# Imagine X Memory System

[Back to docs index](../README.md)

## Purpose

Define memory that lets Axiom Imagine X improve across sessions while staying explainable.

## Memory Layers

- Brand Memory: identity, colors, fonts, tone, logo rules, compliance notes.
- Style Memory: visual preferences, composition patterns, lighting, color harmony, typography taste.
- Project Memory: active project goals, recent prompts, accepted directions, rejected directions.
- Creative Memory: outcome ratings, preference clusters, workflow patterns, model performance.
- Provider Memory: latency, cost, quality, failure rate, capability fit by studio.

## Outcome Contract

Every generation or Imagine X-assisted result should log:

- Studio.
- Prompt and refined intent.
- Provider route.
- Duration and failure state.
- Output object count.
- Accepted/rejected status.
- User rating and feedback.
- Follow-up edits.

## Learning Rule

Memory must explain recommendations. A route, style suggestion, or prompt refinement should be traceable to outcomes, brand rules, or user feedback.

## Locked Baseline

Changes require an ADR.
